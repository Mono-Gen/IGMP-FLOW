# IGMP-FLOW 利用マニュアル

必要なもののインストール、ネットワークへの接続方法、画面の見方、困ったときの対処を説明します。概要は [README_JP.md](../README_JP.md)、
英語版は [manual_EN.md](manual_EN.md) をご覧ください。

## 1. 必要なもの

### 1.1 ハードウェアとネットワーク

| もの | 理由 |
|---|---|
| 有線ネットワークポート（NIC）のある Windows 10/11 の PC | IGMP-FLOW を動かし、パケットを取得します |
| **ポートミラーリング（SPAN）のできるマネージドスイッチ** | 他の機器の通信を PC で見るために必要です。無いと、この PC 自身の通信と、わずかなブロードキャスト/マルチキャストしか見えません |
| （任意）USB など 2 枚目の NIC | 監視用のポートと、普段のネットワーク接続を分けられます |

ポートミラーリングは、スイッチ側で設定します（機種によって手順が異なります）。見たいポートや VLAN を「コピー元」、PC をつなぐポートを
「コピー先」にします。IGMP の Report と Query を見るには、クエリアへのアップリンクと、見たい機器のポートをミラーしてください。
仮想アダプタ（Hyper-V や VPN など）では、ホスト自身の通信しか見えません。

### 1.2 インストールするソフトウェア

| ソフトウェア | 必須か | 補足 |
|---|---|---|
| **Npcap** | **必須（Windows）** | パケット取得ドライバです。<https://npcap.com/> から入手し、既定のオプションでインストールします。IGMP-FLOW には**同梱されておらず**、独自のライセンスがあります（無料版は利用に制限があり、再配布不可。大規模な導入や商用では、有料の OEM ライセンスが必要な場合があります）。既定でインストールしてもキャプチャできない場合は、Npcap を入れ直し、**「Install Npcap in WinPcap API-compatible Mode」**にチェックを入れてください |
| 新しいブラウザ（Edge、Chrome、Firefox） | 必須 | 画面はブラウザで表示します。画面を表示する PC には**インターネット接続が必要**です（2 つの画面部品、vis-network と Font Awesome を公開 CDN から読み込むため） |
| Python 3.12 | ソースから実行する場合のみ | `IGMP-FLOW.exe` を使う場合は不要です |
| Python パッケージ `scapy`、`websockets` | ソースから実行する場合のみ | `python -m pip install -r requirements.txt` |
| Wireshark | 任意 | IGMP-FLOW が出力する `.pcap` を開くのに便利です。必須ではありません |

データベース、ウェブサーバー、その他のサービスは**インストール不要**です。自分の PC の外には何も待ち受けません
（画面用のサーバーも WebSocket も、`127.0.0.1` だけで待ち受けます）。

### 1.3 権限

Npcap のインストール方法によっては（例：「Restrict Npcap driver's access to Administrators only」を選んだ場合）、キャプチャに**管理者権限**が
必要です。NIC の一覧が空、またはキャプチャが始まらない場合は、管理者として実行してください（右クリック → 管理者として実行）。

`IGMP-FLOW.exe` にはコード署名がないため、初回は Windows SmartScreen の警告が出ることがあります。入手元が信頼できるビルドだけを実行するか、
ソースから実行してください。

## 2. 起動と終了

1. PC をミラーポートにつなぎ、NIC に IP アドレスが付いていることを確認します（任意のアドレスで構いません。リンクローカルでも可）。
2. `IGMP-FLOW.exe` を起動します（またはプロジェクトのフォルダで開いたターミナルから `python app.py`）。
3. ブラウザで `http://localhost:8000` が開きます。右上が **Live monitoring (connected)** になっていることを確認してください。
4. 上部のプルダウンで、ミラーポートにつながっている NIC を選びます（自動で選ばれますが、正しいか確認してください）。

終了するには、上部バーの **Exit** を押して確認します。ブラウザのタブを閉じても、アプリは**停止しません**（監視と PCAP 記録は続きます）。ブラウザを閉じると、
終了するかを尋ねるダイアログが出ます（無人で記録し続けるときは、`--no-close-prompt` を付けて起動すると出なくなります）。2 つ目を起動した場合は、
既存のページを開くだけです。

機材が無くても画面を試せます：`python scripts/demo_simulator.py` で、サンプルのシナリオが再生されます。

## 3. 画面の見方

### 3.1 上部バー

- **プロトコルのチェック**（IGMP、PTPv1、PTPv2、mDNS、SSDP、SAP、LLMNR、Dante ConMon、Dante audio、sACN、AES67 audio、Other multicast）：
  ログ、Stream stats、図に表示する対象を選びます。絞り込みはプログラム側で行い、**全パケットは引き続き PCAP に記録されます**。
  図では、チェックを外した種類のグループを隠します（sACN か Dante か未確定の 239.255.x.x のグループは、両方を外したときだけ隠します）。
  *IGMP* を外すと、受信側（Join）の線を隠します。
- **PTP types**：PTP のメッセージ種別を絞ります（例：Announce だけ）。
- **絞り込み欄**：IP、MAC、グループ、機器名に、入力した文字を含む通信だけを表示します。図では、一致したグループと機器、
  およびそれにつながるものだけを表示します。
- **Show data plane per packet**：音声ストリームは通常 1 秒ごとの集計で表示します。チェックすると 1 パケットずつ表示します（狭い絞り込みと併用してください）。
- **Export CSV**：期間（`YYYY-MM-DD HH:MM:SS`、ローカル時刻）と音声の扱いを選べます。
- **Stop capture / Start capture**、**Exit**。
- **状態チップ**：*Querier*（IGMP クエリアは誰か。検出できないと赤）、*PTP*（警告）、*PCAP*（記録パケット数、取りこぼし）。
- **No Join/Leave seen**（黄色のチップ）：Query は届いているのに、General Query から 30 秒たっても他の機器の IGMP Report が 1 件も見えない状態です。
  IGMP スヌーピングでは Report がスイッチのルーター（クエリア）側ポートにしか送られないため、多くの場合、PC がミラー（SPAN）ポートではなく
  通常のポートにつながっています。どの機器もグループに参加していない場合にも表示されます。この PC 自身の Report は数えません。
  他の機器の Report を 1 件でも観測すると消え、リセットや NIC 切替のあとに改めて判定します。

### 3.2 トポロジ図（上の領域）

- 紫の王冠：IGMP **クエリア**。緑の人型：マルチキャスト**グループ**。青のノート PC：**機器**。橙の時計：**PTP クロック**の送信元。
- 機器からグループへの線は、その機器が参加（Join）していることを示します。離脱（Leave）すると線は消えます。
- 右下のボタン：全体表示、レイアウトの固定/再開（監視は止まりません）、**再起動**（図・ログ・監視を初期化し、PCAP を新しいファイルに切り替えます。図は、以降に届く
  Query/Report から作り直されます。通常は Query の間隔、約 125 秒以内）。
- 図と下パネルの間のバーをドラッグすると高さを変えられます。ダブルクリックで初期位置に戻ります。**Maximize** で下パネルを広げられます。

### 3.3 下パネルのタブ

- **Log**：イベントごとに 1 行（時刻、プロトコル、イベント、ホスト、グループ）。**Pause log** は、このログへの追加だけを止めます。
- **PTP status**：クロックとメッセージ種別ごとに、*実測*の間隔と、クロックが*宣言*する間隔、グランドマスター ID、プライオリティを表示します。
  Announce の途絶、同じドメインでの複数のグランドマスター、間隔の不一致を警告します。
- **Stream stats**：ストリームのデータ（Dante audio、sACN、AES67 audio、その他のマルチキャスト）を、パケット/秒と bit/秒で、1 秒ごとに更新します。
  表示されるのは、このポートに届いたストリームだけです。IGMP-FLOW は自分からグループに Join しません（上部の *Passive* 表示）。
  そのため IGMP Snooping 環境では、ミラー（SPAN）ポートか、マルチキャストをフラッディングするスイッチでないとストリームは見えません。
- **図のグループの色**：色付きは、直近数秒にこのポートでストリームのデータを観測したグループです。灰色は、このポートでは観測していないグループです。
  灰色は異常ではなく、ストリームが止まったという意味でもありません。
- **グループのアイコン**：電球は sACN（照明）、スピーカーは Dante audio、波形は AES67 audio です。sACN と Dante はどちらも
  239.255.x.x を使い、IGMP の Join にはポート番号が含まれないため、239.255.x.x のグループは、このポートでデータを観測するまで
  疑問符（「sACN universe N or Dante」）で表示します。
- **まとめノード**：グループが 40 個を超えると、同じアドレス範囲（例: 239.255.x.x のうち sACN/Dante の範囲）のグループを 1 つのノードにまとめ、
  グループの数とデータを観測した数を表示します。機器が 30 台を超えると、同じ /24 サブネットの機器を 1 つのノードにまとめます。
  クエリアと PTP クロックは常に個別に表示します。まとめノードをダブルクリックすると中身を表示し、表示されたノードを
  ダブルクリックすると、もう一度まとめます。まとめている数は状態バーに表示します。
- **送信元**：機器からグループへのオレンジの矢印は、その機器からそのグループへのストリームのデータを、直近数秒にこのポートで
  観測したことを示します。矢印の無い青い線は受信側（IGMP の Join）です。送信元が分かるのは、ストリームがこのポートに届く
  場合（ミラーポート）だけです。届かない場合、グループのツールチップには「Senders: unknown on this port」と出ます。
  送信元がいないという意味ではありません。受信機が送信元を指定している場合（IGMPv3）は、それもツールチップに出します。
- **グループの ⚠**：同じグループに送信元が 2 台以上いる（マルチキャストアドレスの重複設定を確認）、またはデータが届いて
  いるのに受信者の Join が無い、のどちらかです。後者は、このポートで他の機器の Join が見えている場合（*No Join/Leave seen*
  チップが出ていない場合）だけ判定します。どちらに当たるかは、グループにマウスを乗せると表示されます。
- **ノードをクリック**すると、そのノードとつながるものだけを強調し、ほかを薄くします。空白をクリックすると元に戻ります。

## 4. よくある使い方

- **誰がどのグループに参加している？** 図を見るか、ログを *IGMP* で絞り、グループのアドレスを絞り込み欄に入力します。
- **IGMP クエリアはいる？** *Querier* チップを確認します。「No querier!」はスイッチの IGMP スヌーピングが働かない恐れ、「Multiple queriers」は
  全クエリアと、本来選ばれるべきもの（最小の IP）を表示します。Query のバージョン（v1/v2/v3）、ロバストネス、間隔は、ログの詳細と CSV で見られます。
- **全部見えている？** 黄色の *No Join/Leave seen* チップが出ていないこと、気になるグループが灰色ではなく色付きで表示されていることを確認します。
  そうでなければ、PC が IGMP スヌーピング有効スイッチの通常ポートにつながっている可能性が高いので、ミラー（SPAN）ポートにつなぎ替えます（1 章参照）。
- **クロックは正常？** *PTP status* を開きます。Dante は PTPv1、AES67/ST 2110 は PTPv2 を使い、両方が共存できます。ドメインごとにグランドマスターが 1 台だけ
  Announce していること、実測間隔が宣言値と合っていることを確認してください。
- **余計な通信を探す：** *SSDP*、*LLMNR*、*Other multicast* だけにチェックすると、音響ネットワークに流れているオフィス用や不明なマルチキャストが見えます。
- **何時間も何日も記録する：** アプリを起動したままにします（`--no-close-prompt` 推奨）。全て PCAP に記録されます。PCAP は自動では削除されないため、ディスクの空きに
  注意してください（フォルダが大きくなると、PCAP チップが警告します）。
- **後から分析する：** **Export CSV** を使うか、`.pcap` を Wireshark で開きます。

## 5. ファイルの保存場所

| 内容 | 場所 |
|---|---|
| PCAP の記録、CSV の出力、ログ | `%LOCALAPPDATA%\IGMP-FLOW\data\`（`captures`、`exports`、`logs`）。環境変数 `IGMP_FLOW_DATA_DIR` で変更できます |
| CSV の列 | Timestamp、Event、Device Name、IP Address、MAC Address、Multicast Group、Protocol、Packets、Detail、Event Code |

PCAP は、音声パケットをヘッダのみ（先頭 128 バイト）で保存して容量を抑え、制御系（IGMP、PTP、mDNS など）は全長で保存します。
これらのファイルには、実際の IP/MAC アドレスと機器名が含まれます。機密として扱い、公開の場所にアップロードしないでください。

コマンドラインでの出力：

```
python -m backend.pcap_export <file.pcap> -o out.csv --proto IGMP --proto PTPv2 --ptp-type Announce --since "2026-01-01 10:00:00"
```

アプリの起動オプション：`-i/--interface`、`--interactive`、`-p/--port`、`--capture-dir`、`--no-pcap`、`--live-csv igmp|all|off`、`--no-close-prompt`。

## 6. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 起動時に「Npcap がインストールされていません」 | Npcap をインストール（1.2 節）して、再起動する |
| NIC の一覧が空、または何も取得されない | 管理者として実行する。Npcap の導入を確認する。ミラーポートにつないだ NIC を選ぶ。スイッチ側のミラー設定を確認する |
| 図がラベルの塊になって読めない | 0.2.2 以降に更新する。グループや機器が多いとまとめノードで表示する |
| 照明（sACN）のネットワークなのに「Dante」と表示される | 0.2.2 で修正。sACN と Dante を UDP ポートで見分ける。Join しか見えていないグループは「sACN universe N or Dante」と表示する |
| グループが図に出ているのに灰色、または Stream stats に出ない | IGMP Snooping 環境でミラーではないポートなら正常。IGMP-FLOW は Join しないので、スイッチがこのポートへストリームを転送しない。ストリーム本体を見るにはミラー（SPAN）ポートを使う |
| 「No Join/Leave seen」が表示される | PC が IGMP スヌーピング有効スイッチの通常ポートにつながっている。クエリアへのアップリンク（または機器のポート）を、この PC のポートへミラーする |
| この PC 自身の通信しか見えない | そのポートがミラー（SPAN）ポートではない、または NIC が仮想アダプタ |
| 機器の Join/Leave が出てこない | Join は、機器が購読を始めたとき、または Query への応答として更新するときに送られます。次の Query（約 125 秒）を待つか、機器をつなぎ直す |
| 画面に「Disconnected (reconnecting...)」と出る | アプリが動いていない、または別のインスタンスがポート 8765 を使っている。アプリを起動する（または他方を終了する） |
| ページは開くが、図やアイコンが出ない | PC がインターネットにつながっていない（CDN の部品を読み込めない） |
| 更新後も古い画面のまま、または日本語と英語が混ざる | アプリを完全に再起動する（ブラウザを閉じても古いプロセスが動き続けます）。画面は Ctrl+F5 で再読み込みする |
| 「UI HTTP server could not start (port 8000)」 | 別のプログラムがポート 8000 を使っている。それを終了する |
| CSV の名前に `'=...` のような文字が出る | 仕様です。`=`、`+`、`-`、`@` で始まる名前は、表計算ソフトが数式として実行しないよう、先頭に `'` を付けています |
| アプリが終了しない | **Exit** を使う。更新前に起動したアプリは、ボタンを無視する場合があるため、タスクマネージャーで `IGMP-FLOW` を終了する |

## 7. アンインストール

プログラムのフォルダ（または `IGMP-FLOW.exe`）と、データフォルダ `%LOCALAPPDATA%\IGMP-FLOW` を削除します。Npcap は別のプログラムなので、
*設定 → アプリ* から削除してください。

## 8. プライバシーとセキュリティの要点

IGMP-FLOW は受動的で（自分からは送信しません）、`127.0.0.1` だけで待ち受け、他のウェブページからの接続を拒否し、ネットワーク由来のデータを信頼しません。
ログイン機能はないため、ポート 8000/8765 を PC の外へ公開しないでください。詳細は README を参照してください。

## 9. 既知のマルチキャストグループ

IGMP-FLOW は次のアドレスに、図とログで名前を付けて表示します。見かけたアドレスを調べるときに使ってください。
表に無いアドレスでも、異常とは限りません。同じ PC や機器で動いている別のソフト（照明・制御・AV 用のソフトなど）が、
独自のグループに参加していることがあります。*出典* 列は、各行を確認した資料です。

| アドレス | ポート（UDP） | プロトコル / 用途 | IGMP-FLOW での表示 | 出典 |
|---|---|---|---|---|
| 224.0.0.1 | – | IGMP：全ホスト（General Query の宛先） | All Hosts | IANA マルチキャスト登録簿 |
| 224.0.0.2 | – | IGMP：全ルーター（IGMPv2 の Leave の宛先） | All Routers | IANA マルチキャスト登録簿 |
| 224.0.0.22 | – | IGMPv3 のメンバーシップレポート | IGMPv3 Reports | IANA マルチキャスト登録簿 |
| 224.0.0.107 | 319, 320 | PTP のピア遅延測定 | PTP peer delay | IANA マルチキャスト登録簿 |
| 224.0.1.129 | 319, 320 | PTP のクロック同期（既定ドメイン。Dante は PTPv1、AES67 は PTPv2） | PTP clock sync | IANA、Audinate |
| 224.0.1.130 – 224.0.1.132 | 319, 320 | PTP のクロック同期（その他のドメイン） | PTP clock sync (alternate domain) | IANA、Audinate |
| 224.0.0.230 – 224.0.0.233 | 8700 – 8708 | Dante の制御と監視（ConMon） | Dante control & monitoring | Audinate |
| 224.0.0.251 | 5353 | mDNS（Bonjour）：機器の発見。Dante Controller が使う | mDNS | IANA、Audinate |
| 224.0.0.252 | 5355 | LLMNR（Windows の名前解決）。AV ネットワークには不要 | LLMNR | RFC 4795 |
| 239.254.3.3 | 9998 | Dante の PTP ログ（有効にした場合のみ） | Dante PTP logging | Audinate |
| 239.255.255.250 | 1900 | SSDP / UPnP の発見（オフィス機器、Windows） | SSDP | UPnP Device Architecture |
| 239.255.255.255 | 9875 | SAP：AES67 のストリーム告知 | SAP | RFC 2974 |

IGMP-FLOW がアドレスと**ポート**で見分ける範囲：

| アドレス範囲 | ポート（UDP） | プロトコル / 用途 | IGMP-FLOW での表示 | 出典 |
|---|---|---|---|---|
| 239.255.0.0 – 239.255.249.255 | 5568 | sACN（ANSI E1.31）の照明データ。ユニバース N は 239.255.(N÷256).(N mod 256) | sACN universe N | ANSI E1.31（照明メーカーのマニュアル経由） |
| 239.255.0.0/16 | 4321 | Dante のマルチキャスト音声・映像 | Dante audio | Audinate |
| 239.x.x.x のいずれか | 5004 | AES67（RTP）音声。239.69.x.x がよく使われる既定値だが、機器ごとに変えられる | AES67 audio | AES67 対応メーカーの資料 |

sACN と Dante はどちらも 239.255.x.x を使います。IGMP の Join にはポート番号が含まれないため、Join だけが見えている
239.255.x.x のグループは、このポートでデータを観測するまで「sACN universe N or Dante」と表示します。

出典：IANA *IPv4 Multicast Address Space Registry*、Audinate *Dante Information for Network Administrators*、
RFC 2974（SAP）、RFC 4795（LLMNR）、UPnP Device Architecture（SSDP）、ANSI E1.31（sACN）。
